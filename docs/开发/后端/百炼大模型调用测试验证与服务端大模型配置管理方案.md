### 多模态内容类型标识

请求中的`type` 是多模态内容类型标识（Discriminator），用于告诉 API 当前传入的是文本、图片、视频还是音频；`text` 则是 `type: "text"` 对应的内容字段。它们是 OpenAI 兼容协议规定的字段，不能随意改名，但 `type` 可以使用不同的枚举值。

阿里云百炼的 Chat Completions 接口支持以下内容类型：

| type          | 对应内容字段  | 用途                   |
| ------------- | ------------- | ---------------------- |
| `text`        | `text`        | 传入普通文本           |
| `image_url`   | `image_url`   | 传入图片 URL 或 Base64 |
| `video_url`   | `video_url`   | 传入视频文件           |
| `video`       | `video`       | 传入视频帧列表         |
| `input_audio` | `input_audio` | 传入音频数据           |

注意，并不是所有模型都支持全部类型。当前使用的 `qwen3.8-flash` 支持文本、图片、视频输入，输出文本；不支持音频输入。如果需要音频理解，可以考虑 `qwen3.8-omni-flash`。

#### 不同类型的 JSON 写法

普通文本

```
{
  "type": "text",
  "text": "你好，请介绍一下自己"
}
```

图片

```
{
  "type": "image_url",
  "image_url": {
    "url": "https://example.com/image.png"
  }
}
```

视频文件

```
{
  "type": "video_url",
  "video_url": {
    "url": "https://example.com/video.mp4",
    "fps": 2
  }
}
```

视频帧列表

```
{
  "type": "video",
  "video": [
    "https://example.com/frame1.jpg",
    "https://example.com/frame2.jpg"
  ]
}
```

音频（需使用支持音频的模型）

```
{
  "type": "input_audio",
  "input_audio": {
    "data": "data:audio/wav;base64,...",
    "format": "wav"
  }
}
```

上述是不同模态的字段结构，具体是否可用由模型能力决定。

**纯文本可以简化，不必指定 type**

对于纯文本请求：

```
{
  "role": "user",
  "content": "你好，请介绍一下自己"
}
```

等价于：

```
{
  "role": "user",
  "content": [
    {
      "type": "text",
      "text": "你好，请介绍一下自己"
    }
  ]
}
```

只有需要混合文本、图片等不同模态时，才通常使用 `content` 数组。

#### 与 Responses API 的区别

OpenAI 还有另一套 `/responses` 接口，其类型命名不同：

| Chat Completions | Responses API |
| ---------------- | ------------- |
| `text`           | `input_text`  |
| `image_url`      | `input_image` |

两种接口不能直接混用参数格式。百炼也提供了相应的 Responses 兼容协议。

对于你现在的 `qwen3.8-flash` 调用，推荐继续使用 `/chat/completions`，图片用 `image_url`，文字用 `text`。 这是标准且兼容性较好的写法。

# 如何在服务端管理模型

目前Spring AI框架支持多模型的调用配置，但需要区分“模型能力支持”和“多模型配置管理”两件事。

截至 2026 年 10 月 29 日，Spring AI 最新稳定版为 2.0.2，已经提供聊天、向量、多模态视觉和图片生成等模型能力的统一抽象。不过，Spring AI 并不是一个开箱即用的多模型注册中心。

## Spring AI 版本兼容关系

| Spring Boot       | 建议 Spring AI 版本 |
| ----------------- | ------------------- |
| Spring Boot 3.5.x | Spring AI 1.1.8     |
| Spring Boot 4.x   | Spring AI 2.0.2     |

Spring AI 2.x 对配置项和底层 OpenAI SDK 有较大调整，因此以下的 YAML 是按 2.0.2 编写的，不应直接照搬到 1.1.x。

## Spring AI 支持情况

| 模型类型            | Spring AI 接口             | 支持情况 |
| ------------------- | -------------------------- | -------- |
| 文本模型            | `ChatModel` / `ChatClient` | 原生支持 |
| 向量模型            | `EmbeddingModel`           | 原生支持 |
| 视觉理解模型        | `ChatModel` + `Media`      | 原生支持 |
| 文生图模型          | `ImageModel`               | 原生支持 |
| 图文生图 / 图片编辑 | `ImageModel` + 厂商扩展    | 需要适配 |

其中最容易混淆的是：

- 视觉理解不是独立的 `VisionModel`。它属于多模态 Chat，使用 `UserMessage` 传入文字和图片。
- 文生图属于 `ImageModel`，与 Chat 是不同的模型接口。
- 图文生图没有完全统一的跨厂商调用规范。尤其是百炼的 `qwen-image-3.0`，虽然使用 OpenAI 兼容路径，却需要额外传入 `image` 字段。

目前测试的百炼模型，可以这样对应：

| 百炼模型                  | Spring AI 使用方式           |
| ------------------------- | ---------------------------- |
| `qwen3.8-flash` 文本生成  | `ChatModel`                  |
| `qwen3.8-flash` 图片理解  | 同一个 `ChatModel`           |
| `qwen3.7-text-embedding`  | `EmbeddingModel`             |
| `qwen-image-3.0` 文生图   | `ImageModel`，需验证兼容行为 |
| `qwen-image-3.0` 图文生图 | 单独适配图片输入             |

## 如何配置多类大模型配置

以 Spring AI 2.0.2 + Spring Boot 4.x 为例，一个 OpenAI Starter 就可以同时提供 Chat、Embedding 和 Image 的自动配置。

### Maven 依赖

```
<dependencyManagement>
    <dependencies>
        <dependency>
            <groupId>org.springframework.ai</groupId>
            <artifactId>spring-ai-bom</artifactId>
            <version>2.0.2</version>
            <type>pom</type>
            <scope>import</scope>
        </dependency>
    </dependencies>
</dependencyManagement>

<dependencies>
    <dependency>
        <groupId>org.springframework.ai</groupId>
        <artifactId>spring-ai-starter-model-openai</artifactId>
    </dependency>
</dependencies>
```

### application.yml

```
spring:
  ai:
    model:
      chat: openai
      embedding: openai
      image: openai

    openai:
      base-url: https://ws-xuj64ag8x47upqti.cn-beijing.maas.aliyuncs.com/compatible-mode/v1
      api-key: ${DASHSCOPE_API_KEY}

      # 文本生成 + 视觉理解
      chat:
        model: qwen3.8-flash

      # 向量模型
      embedding:
        model: qwen3.7-text-embedding
        dimensions: 1024
        encoding-format: float

      # 文生图模型
      image:
        model: qwen-image-3.0
        size: 1024x1024
```

上述配置项来自 Spring AI 2.0.2 官方文档，其中 `chat.model`、`embedding.model`、`image.model` 都可以分别设置。

另外，2.0.2 的 OpenAI 集成已经使用官方 `openai-java` SDK，因此这里的 Base URL 包含 `/compatible-mode/v1`，不要再手工拼接 `/v1`。

这样会形成三个不同职责的模型客户端：

## 如何配置单类多种大模型

Spring AI 默认的自动配置主要提供每种模型类型的默认实例，而不是下面这种无限扩展的命名模型清单：

```
# 示例：不是 Spring AI 原生识别的多模型配置格式
spring:
  ai:
    models:
      - name: qwen3.8-flash
      - name: qwen-plus
      - name: deepseek-v3
```

但可以通过运行时参数切换同一提供商、同一兼容协议下的模型。

例如：

```
String result = chatClient.prompt()
    .user("你好")
    .options(OpenAiChatOptions.builder()
        .model("qwen-plus")
        .build())
    .call()
    .content();
```

这不需要创建一个新的 `ChatModel`，只是在调用时覆盖默认模型。

如果切换的是不同厂商、不同 API Key、不同 Base URL，则需要配置多个客户端实例，或者实现模型连接管理。

## 如何兼容需要适配的大模型

比如图文生图现在，SpringAI框架还不兼容百炼的格式，是需要特别处理的部分。

百炼的 `qwen-image-3.0` 使用的是：

```
POST /compatible-mode/v1/images/generations
```

图文生图通过请求体扩展字段实现：

```
{
  "model": "qwen-image-3.0",
  "prompt": "将这张图片转换成日系插画风格",
  "image": "https://example.com/input.png"
}
```

但 Spring AI 的标准 `ImagePrompt` / `OpenAiImageOptions` 主要覆盖文本提示词、模型、图片数量、尺寸等参数，并没有对应百炼这个扩展 `image` 字段的标准配置。

因此建议：

- 文本、向量、视觉理解：优先使用 Spring AI 原生接口。
- 纯文生图：优先测试 `ImageModel` 的兼容性。
- 图文生图：使用 Spring `RestClient` 或已有 HTTP 组件封装百炼专属调用，不强行套入不完整的通用接口。

## 未来的模型管理策略

可以考虑把 Spring AI 作为调用框架，把实际模型清单维护在独立配置中。

例如：

```
ai:
  models:
    - id: qwen3.8-flash
      provider: bailian
      capabilities:
        - CHAT
        - VISION

    - id: qwen3.7-text-embedding
      provider: bailian
      capabilities:
        - EMBEDDING

    - id: qwen-image-3.0
      provider: bailian
      capabilities:
        - IMAGE_GENERATION
        - IMAGE_EDIT
```

注意，这只是建议的业务层配置结构，不是 Spring AI 自带的配置属性，需要你自己的模型注册与路由逻辑来解析。

这样比把每个模型都注册成独立 Spring Bean 更适合动态模型管理，但对于当前只有三四个模型的场景，没必要一开始就增加注册中心。
